# RFC-0004 — CQIS: Canonical Quantised Inference Semantics

Status: Accepted · Version: 0.1.0 · Depends: RFC-0003

## 1. Purpose
Finite fields prove integers, not floats. CQIS is a deterministic, hardware-independent, integer-only
definition of a transformer forward pass, **designed for the proof and validated for the model** (PRD G7).
A `cqis_id = H(spec_version ∥ model_config ∥ table_ids ∥ scale_format)` identifies it. Providers that want
proofs serve CQIS arithmetic (bit-reproducible on CPU and GPU); the harness is the reference.

## 2. Number formats
| Tensor class | Format | Notes |
|---|---|---|
| Weights (all matmuls, embeddings, LM head) | int8 symmetric, per-output-channel scale `s_w[j] = m_w[j]·2^{e_w}`, `m_w ∈ [1, 2¹⁶)`; optional int4 (`w4`) | integer scale mantissa + per-tensor exponent ⇒ exact integer requant |
| Matmul inputs | int8 symmetric, per-position dynamic scale `s_x[i] = ceil(maxabs_i / 127)` (or static per-tensor) | attained-max proof (§5.5) |
| Residual stream, norm outputs pre-quant, SiLU/gate path, attention output | int16 fixed point with per-tensor exponent | the "wide path" |
| Accumulators | exact integers (int32 budget), never rounded inside a sum | field-faithful by §6 |
| Attention scores | int (q·k as int8·int8 over `d_h`), shift to `[−2^B, 0]` | B = 14 default |
| Probabilities | `P̂ = exp_q(s − m) ∈ [0, 2^E]`, `E = 12` default | unnormalised; normalised at the output |
| Norm statistic | exact Σx² as 3 limbs; `rsqrt_q` via decomposable table | §5.3 |

## 3. Layer definition (Llama-style; variants in RFC-0017)
```
R_0      = Emb[T]                                   (int16; embedding rows are int8·s_e, rescaled)
for ℓ in 0..L:
  X1     = requant8( RMSNorm_q(R_ℓ; g1_ℓ) )          # int8, per-position scale
  Q,K,V  = requant16( X1·W_Q, X1·W_K, X1·W_V )       # int32 accum → int16 (Q,K) ; V → int8
  Q,K    = RoPE_q(Q,K; pos)  → requant8 (Q to int8·2^?, K to int8)   # §5.4
  S      = Q·Kᵀ per head (int), masked
  m_i    = max_j S(i,j) (attained, §5.5); P̂ = exp_q(S − m_i) ∈ [0,2^E]; Z_i = Σ_j P̂(i,j)
  A      = requant8( (P̂·V) / Z_i )                   # output-side normalisation, §5.6
  R_mid  = R_ℓ + requant16( A·W_O )
  X2     = requant8( RMSNorm_q(R_mid; g2_ℓ) )
  U,G    = requant16( X2·W_up ), requant16( X2·W_gate )
  H      = requant8( silu_q(G) ⊙ U )                 # silu_q: int16 → int16 table (decomposed), product → int32 → int8
  R_{ℓ+1}= R_mid + requant16( H·W_down )
logits   = requant16( RMSNorm_q(R_L; g_f) )·W_lmᵀ   (int32)
```
All `requantN(x·s)` are defined as `round_half_even((acc·m) >> e)` with `(m, e)` public per output channel and
position; the quotient/remainder decomposition is what is proven (§5.1).

## 4. Nonlinear primitives are tables
| Table | Domain → range | Size | Decomposition |
|---|---|---|---|
| `exp_q` | `[−2^B, 0] → [0, 2^E]` | 2^B | `exp_q(t) = (T_hi[t ≫ 7] · T_lo[t & 127]) ≫ E` with both sub-tables 2⁷ … CQIS *defines* exp_q this way |
| `silu_q` | int16 → int16 | 2¹⁶ | direct (2¹⁶ is cheap) or hi/lo split with correction table |
| `rsqrt_q` | normalised mantissa (16 bit) × exponent → int16 | 2¹⁶ × small | exponent handled by shift |
| `range_b` | `[0, 2^b)` | 2^b | b ∈ {8, 12, 16} |
| `gelu_q`, `softcap_q`, `sigmoid_q` | as needed (RFC-0017) | ≤ 2¹⁶ | |
Tables are public, generated by the harness from closed-form definitions, committed in the passport (RFC-0011),
and evaluated as MLEs by the verifier (RFC-0016 §4).

## 5. Sub-protocol-shaped definitions (each maps to one reduction)
### 5.1 Requantisation
`acc·m = y·2^e + r`, `0 ≤ r < 2^e`, `y` in the target range (int8/int16) ⇒ one zerocheck + `range_e(r)` (decomposed) + the target range implied by the consuming table or an explicit `range` lookup. Rounding half-to-even: `r ≤ 2^{e−1}` with tie rule proven by one extra bit lookup; CQIS v0.1 uses **round-half-away** (`acc·m + 2^{e−1}` then floor) to avoid the tie gadget. Default.
### 5.2 Residual add
Integer add in int16 with saturation disabled: the bound certificate guarantees no overflow of int16 (sum of two in-range int16 plus margin) — enforced by a `range_16` lookup on the result only where the certificate demands.
### 5.3 RMSNorm
`S_i = Σ_k x(i,k)²` with `x` int16: split `x = x_h·2⁸ + x_l` (`x_h ∈ [−128,127]`, `x_l ∈ [0,256)`), prove three sums
`Σx_h², Σx_h x_l, Σx_l²` (each < 2³⁰ for `d ≤ 2¹⁴`; for larger `d` chunk), recompose `S` into limbs with range checks,
normalise `S = M·2^{2a}` (`M ∈ [2¹⁵, 2¹⁶)`) via bit-length witness `a` and range checks, `inv_i = rsqrt_q(M, a)`,
`y = requant8(x·inv_i·g)`. Cost O(n·d) + O(n) lookups.
### 5.4 RoPE
`(x_{2t}, x_{2t+1}) ↦ (x_{2t}c − x_{2t+1}s, x_{2t}s + x_{2t+1}c)` with `c, s` public int16 tables indexed by `(pos, t)`
(cos/sin scaled by 2¹⁴, rounded). Linear ⇒ one zerocheck with the public MLE of the rotation tables + requant.
### 5.5 Attained maximum (dynamic scales and softmax shift)
For a prover-chosen `m_i`: (i) the consuming table's domain bounds every `x − m_i` (implicit range), (ii) a selection
sumcheck proves `∃ j*_i: x(i, j*_i) = m_i` with `j*` a committed index vector (RFC-0009 §4). Scales: `s_x[i]` is
attained if `127·s_x[i] − maxabs_i < 127`; proven by the same gadget on `|x|` with a sign-bit witness.
### 5.6 Softmax normalisation at the output
`A(i,·)·Z_i = (P̂·V)(i,·) + ρ(i,·)` with `0 ≤ ρ < Z_i` — division by a per-position witness; `Z_i` is a sumcheck
claim (row sum of the virtual `P̂`), `ρ` range-checked against `Z_i` by a comparison gadget (`Z_i − ρ − 1 ∈ range_{E+log n}`).
### 5.7 Blockwise attention accumulation (long context)
For `n·2^{E+7} ≥ 2³⁰`, CQIS defines `(P̂·V)(i,·) = Σ_b requant_c( Σ_{j∈block b} P̂(i,j)V(j,·) )` with block size
`2^{10}` and intermediate rounding to int16 (`c` bits dropped, public). Deterministic; each block sum is a virtual tensor.
### 5.8 Embedding and LM head
`Emb` gather = one-hot matmul (sparse X side, one pass over `E`); LM head = matmul with `W_lm` (or tied `E`); logits int32 → int16.

## 6. Bound certificates (ST-11)
The quantiser emits, per reduction instance, `(max_abs_in_a, max_abs_in_b, inner_dim, bound = ∏ … , field_half)` and asserts
`bound < field_half`. The certificate is part of `cqis_id`; the verifier recomputes it from shapes and formats and
**refuses to verify** a proof whose certificate fails (it is a config error, not a proof error). No reduction may be
instantiated without a certificate line (INV-5).

## 7. Decoding
- `greedy`: for each generated position `t`, `argmax_j logits[t−1, j] = T[t]`: prove `logits[t−1, T[t]] − logits[t−1, j] ≥ 0 ∀j` via `range_{16+}` on the differences (tie-break: lowest index wins; equality allowed only for `j > T[t]`).
- `sampled(seed_commitment, temperature, top_p)`: CQIS defines `softmax_q` over logits (same gadgets), the CDF in fixed point, `u_t = H(seed ∥ t)` reduced to the CDF scale, and the chosen token as the CDF bucket containing `u_t`; top-p as a prefix-sum threshold with an attained-boundary gadget.
- Stop at EOS or `max_tokens`; the statement covers exactly the published continuation length.

## 8. Fidelity protocol (harness, E5)
Report perplexity (WikiText‑2, 4k context), GPQA‑Diamond, MMLU‑Pro, IFEval for fp32 vs CQIS on the same items with paired
standard errors; publish in the passport. Acceptance: PRD G7. Knobs if it fails: int16 → int24 wide path (uses DPA),
static → dynamic scales, per-group weight scales (DPA), `B/E` bits for attention.

## 9. Decode equals one causal pass
Autoregressive decoding with a KV cache computes, at step `t`, exactly the causal forward pass restricted to position
`t` over prefix `T[0..t]`; concatenating the steps gives the single full-sequence causal pass used by the statement.
The only per-step facts are the decoding checks of §7, which bind `T[t]` to logits at `t−1`. KV-cache int8 precision is
part of CQIS (K int8 after RoPE, V int8), so the serving KV cache must store those values.

## 10. Negative controls
NC-0100 wrong rounding direction; NC-0101 remainder out of range; NC-0102 non-attained scale; NC-0103 non-attained softmax max;
NC-0104 exp index out of domain (score above max); NC-0105 norm statistic limb overflow; NC-0106 RoPE table index mismatch;
NC-0107 tie-break violation in argmax; NC-0108 wrong sampling seed; NC-0109 certificate forged to hide overflow.

## 11. Amendment log

### A1 — Consistent signed round-half-away relation

Status: Accepted. Review record: [A1 skill reviews](../../agents/reviews/field-cqis-a1.md).

Motivation: §3 names half-even, §5.1 names half-away but supplies a half-up formula,
and its unadjusted nonnegative-remainder relation cannot represent rounding up.
`research/cqis-rounding/REPORT.md` gives exact counterexamples. Q10 tracks the issue.

Exact replacement for the paragraph after §3's layer definition:

> All `requantN` operations use signed round-half-away as defined in §5.1, with
> public positive integer mantissa `m` and nonnegative integer right-shift `e`.
> `m ∈ [1, 2¹⁶)`. The input accumulator is an exact signed int32 integer. The result
> must fit the requested signed int8 or int16 format; no saturation or wrapping is
> allowed. An unsupported scale/shift or an out-of-range result is an error.

Exact replacement for §5.1:

> Let `t = acc·m`, `D = 2^e`, `a = |t|`, `b = 1` iff `t < 0` (otherwise zero),
> and `h = 2^(e-1)` for `e > 0`, or `h = 0` for `e = 0`.
> Define `q = floor((a+h)/D)`, `r = a+h-q·D`, and `y = (1-2b)·q`.
> This is round-half-away for either sign, including exact ties and the identity
> shift `e = 0`. All intermediate integer arithmetic is exact and checked; an
> implementation must reject configurations exceeding its supported arithmetic.
>
> The proved relation is `t = acc·m`, `t = (1-2b)·a`, `a+h = q·D+r`,
> and `y = (1-2b)·q`, with `b ∈ {0,1}`, nonnegative bounded `a,q`,
> `0 ≤ r < D`, and `y` in the target signed range. The sign witness is canonical:
> `b = 0` when `a = 0`. The bounds and any necessary limb decomposition are static
> certificate data under §6, including the multiplication and biased magnitude.
> Every sign/range check must be enforced by the appropriate consuming lookup or
> an explicit lookup under the range discipline. Witness generation alone does
> not enforce them. No target-range check may be replaced by saturation.

Soundness accounting: no new challenge in this semantic correction. Reduction work
must account for every zerocheck/lookup it instantiates and its actual degree under
RFC-0012 before implementation; no error term or bound is waived by this proposal.
Existing controls NC-0100 and NC-0101 must cover both signed ties and a tampered biased
remainder; NC-0109 must cover the static bounds. No new claim-graph edge is introduced.
Cost model: the sign/magnitude relations contribute to `c_a` when implemented; no
measured constant changes here. Affected tasks: E5-01 (unblocked by A1), E5-03,
E7 requant reductions and their downstream consumers. No existing core arithmetic
implements either disputed formula.

Completed skill review passes (Workflow 02; same authoring agent, not independent review):
- [x] soundness-auditor (codex-root): integer equivalence, sign/range bindings, static bounds
- [x] rfc-author (codex-root): consistency with ADR-005, formats and glossary
- [x] stele-cqis owner / cqis-numerics (codex-root): supported arithmetic, Rust/NumPy parity and error behavior

### A2 — Complete nonlinear table and RMSNorm definitions

Status: Draft. Question Q25. Evidence: [exact table study](../../research/cqis-tables/REPORT.md).
Review: [draft skill passes](../../agents/reviews/cqis-tables-a2-draft.md).

Motivation: §4's inclusive exp domain has 2^B+1 values and its B=14 high
index has 129 values, contradicting the stated sizes. Section 5.3 cannot
normalize valid sum-of-squares values 0, 1, 65536 or 131073. The named
activation tables lack closed forms, complete scales and canonical byte rules.
These are semantic blockers, not implementation latitude. A1 remains in force.

Proposed exact addition to §4, contingent on the complete definitions below:

> Every supported table has a versioned closed-form integer definition with
> explicit input/output scales, parameter bounds, endpoint behavior, rounding,
> overflow rejection, decomposition and canonical row order. Generation and
> verifier evaluation use that same definition. There is no implicit choice of
> activation variant, host floating-point rounding or saturation. The registered
> identity covers all parameters that can change an entry; canonical framing
> and integer encodings are specified with RFC-0008 §4 and RFC-0011 §1.
> Unsupported definitions and malformed parameters fail before table use.
> Error analysis names the reference real function and units, and accounts for
> approximation, rounding and recombination separately. A generator certifies
> the selected integer entries; numerical agreement at a chosen precision alone
> is not a proof of correct rounding or a maximum-error bound.

Required replacements before acceptance (Q25):

1. Replace §4's exp row with exact domain cardinality, index maps, sub-table
   formulas and sizes, input exponent, output exponent and product rounding.
   Preserve the attained-maximum endpoint and specify all supported B/E values.
   Any changed attention domain requires the matching RFC-0009 §2 amendment.
2. Supply exact SiLU, GeLU/tanh-GeLU, sigmoid and softcap formulas and parameter
   encodings, including input/output scales, softcap cap and out-of-range rules.
   Define direct versus decomposed evaluation so it cannot select different
   integer outputs for the same table identity. Range tables need byte/order
   rules even though their sets are already defined.
3. Replace §5.3 normalization with a total integer algorithm over the supported
   sum-of-squares domain, including zero. Resolve parity of the exponent,
   discarded information/remainders, dimension and epsilon semantics, rsqrt
   scaling and the subsequent multiplication/requantisation bounds. A larger
   mantissa interval alone does not make arbitrary statistics exactly divisible.
   State the integer relation and range checks that the reduction must enforce.
4. Complete RFC-0008's identity framing, definition version and parameter bytes,
   signed entry representation, row order, invalid encoding rejection and
   verifier evaluation contract. Coordinate passport and CQIS identity binding
   with RFC-0011; no ad hoc JSON representation is a canonical protocol encoding.
5. Provide reproducible generation certificates and per-table absolute-error
   bounds in stated units. Use exact rational intervals or another explicitly
   justified method; include ties, endpoints, underflow, overflow and worst-case
   decomposition errors. Rust/NumPy integer parity, fixed vectors and one-value
   table/identity/recombination controls remain production delivery requirements.

Soundness impact: no challenge or error term is implemented by this Draft.
Correct table arithmetic does not prove lookup membership, passport identity,
range discipline or static field faithfulness. Future reductions must account
for their actual degree/challenges, and every normalization identity needs §6
certificates and explicit range consumers. Existing NC-0104/0105, NC-0404/0405
and NC-0701 remain obligations; research assertions earn no control credit.
Any new binding needs a catalog control upon acceptance. Q12 is unaffected.

Cost impact: table size/evaluation and decomposition affect c_lu and c_a;
generation and passport storage are one-time costs. No measured constant,
weight-pass count or benchmark changes. Affected tasks: E5-02 (blocked on A2),
E5-03's norm-related certificates, E5-04, E6 table registry, E7 nonlinear/norm
reductions and E10 passport consumers. All original acceptance criteria remain.
E5-01's accepted scalar arithmetic is unchanged. This draft is not sufficient
to implement the missing functions or to claim a complete CQIS forward pass.

Candidate exponential definitions are now specified in
[certified exponential candidates](../../formal/cqis-exp.md). Exact rational
enclosures certify all sub-table entries in a boundary grid and every correctly
rounded entry for the B=14,F=10,E=12 example. The endpoint-safe two-table product
has a strict two-unit error bound but exhibits nonmonotonic steps; a correction
in {-1,0,1,2} makes direct and decomposed evaluation agree with correctly rounded
exp. That correction requires a full indexed table and an additional lookup,
whose cost is explicit. F=10 is an example scale, not a model/default decision.
This resolves a candidate numerical rule and its error argument, not the full
A2 contract: remaining activations, total RMSNorm, canonical registry/passport
bytes, scale alignment, representation selection, production controls and model
fidelity remain required. A2 and E5-02 stay Draft/blocked.

[Strict activation candidates](../../formal/cqis-activations.md) now give exact
scaled sigmoid, SiLU and softcap definitions with signed half-away and overflow
rejection. Strict rational endpoints resolve cases where rounding an asymptotic
limit gives the wrong integer. Independent reciprocal-series checks cover three
complete signed-int16 tables and varied-scale inputs; each certified entry has
at most one-half output-unit error. Direct rows, cap parameters and all costs
remain explicit. This is further numerical evidence, not acceptance: GeLU
variants, total RMSNorm/rsqrt, authenticated registry bytes, complete model-scale
alignment, native controls/parity and fidelity remain required under A2.

### A3 — Canonical quantiser and static certificate contract

Status: Draft. Question Q26. Evidence: [quantiser/bound study](../../research/cqis-bounds/REPORT.md).
Review: [draft skill passes](../../agents/reviews/cqis-bounds-draft.md).
Motivation: E5-03 needs reproducible weight/activation conversion and verifier
certificate recomputation. Scale formats and a tuple sketch do not select those
algorithms or their bytes. Section 5.5's upper inequality alone accepts scales
below the ceiling; the zero row yields scale zero without a conversion rule.
RFC-0003 A2 separately corrects the field-bound dimension endpoints.

Proposed exact replacement for §5.5's final scale sentence:

> Let M be the attained maximum absolute input in its specified integer units.
> The ceiling definition `s=ceil(M/127)` is equivalent to
> `0<=127*s-M<127`, with integer s and nonnegative M. Both inequalities must
> be enforced; the upper inequality alone is insufficient. The proof that M
> is the maximum and attained remains required. The conversion policy must
> separately define the all-zero row, for which this formula gives s=0.
> A nonzero sentinel scale is a semantic change requiring explicit specification.

Proposed exact addition to §6, contingent on complete schemas below:

> The verifier derives certificate bounds from authenticated static shapes,
> formats and accepted CQIS parameters, and compares every supplied field with
> that derivation. Do not trust a supplied bound, dimension or field-half value.
> Checked integer computation must reject overflow and unsupported reductions.
> Every field identity requires enforced integer ranges on both sides; their
> difference must lie strictly between -p and p for residue equality to imply
> integer equality. For centered arithmetic retain each side's strict p/2
> bound, checked without rounding p/2. Native int32 fit alone is insufficient.
> Certificates account for biased magnitude, products, sums, signed outputs,
> remainders and each limb/carry identity. Neither runtime observations nor
> witness generation establish a static bound or enforce a range in the proof.

Open requirements before acceptance:

1. Define supported checkpoint scalar encodings, exact finite conversion and
   nonfinite rejection. Specify per-channel weight rounding, full or narrower
   signed ranges, choice of int8/int4, shared exponent and channel mantissas,
   tie rules and handling of all-zero channels. No machine-dependent float
   conversion or unspecified calibration may determine canonical bytes.
2. Define dynamic input conversion, zero rows, residual scale alignment and
   static fallback policy. Specify its parameters, rounding, error cases and
   any calibration inputs covered by quantiser identity. Keep scalar A1's
   round-half-away/no-saturation rules; do not confuse a weight exponent with
   the scalar Requant right shift. Resolve all affected format/scale uses.
3. Fix `quantiser_id`, `cqis-weights-v1` and certificate byte encodings with
   RFC-0011 §1. Reuse accepted packing where applicable, but define tensor
   order, metadata, scales, framing and rejection of noncanonical encodings.
4. Enumerate per-reduction certificate schemas and their trusted parameter
   sources, result bounds and range consumers. Implementations need a closed
   supported set; an arbitrary operator name or prover-supplied tuple cannot
   authorize a bound. Incorporate RFC-0003 A2 and A1's biased requant relation.
5. Define canonical chunking/carry or explicit unsupported behavior when a
   shape exceeds a bound. Preserve one weight pass and uncommitted virtual
   partial sums. DPA is still a separate research obligation, not an available
   automatic escape. Norm-related schemas depend on A2's completed semantics.
6. Require random-shape property checks against independent exact arithmetic,
   supported-boundary tests, Rust/NumPy conversion parity and actual NC-0109
   under the consuming certificate validator. Tampering each bound/format/
   dimension/modulus field must reject for its stated reason; research checks
   cannot satisfy that production acceptance line.

Soundness impact: no new challenge or production term. Static faithfulness,
attained maxima and range discipline remain separate enforced obligations.
NC-0102 and NC-0109 remain required; new bindings need controls on acceptance.
No prover-supplied number or observed fit can replace a verifier derivation.
Cost impact: quantisation is preparation; certified chunk/carry/requant work
affects c_a and memory. No benchmark constant or weight-pass count changes here.
Affected tasks: E5-03 (blocked on this complete contract), E5-04, E6 lowering,
E7 reductions and E10 checkpoint/passport work. Original acceptance criteria
remain. E5-01 scalar arithmetic and RFC-0003 A1 field recovery are unchanged.
