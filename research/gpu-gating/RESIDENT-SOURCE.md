# Resident source response qualification (E16-40q)

Development-tier research only; ADR-127's core-backend NO-GO remains. This path
uses the existing source kernels and merged E16-40b source interface. It does not
consume E16-40p's construction interface or produce a certificate or proof.

`gpu_source::prepare_resident` returns a root and owns the symbol-major encoding
and every Merkle level on the device. `Resident::response` downloads one column
and its bottom-up siblings, validates canonical M31 words and generates that
column's salt with the production mask stream. The shape is borrowed immutably,
including its private seed. No payload or seed is logged. Invalid indices reject
before copying. Each duplicate request copies again; batch order and transcript
query selection remain the consumer's responsibility (RFC-0010 A9, RFC-0012 A3).

Existing `prepare` remains root-only. Existing `prepare_material` still downloads
all symbols and nodes and assembles all salted columns with its original root
check. The benchmark CLI retains that complete-material meaning.

For `R = shape.rows()`, `N` encoded columns and `h = log2 N`, preparation downloads
the root's 32 bytes. Each successful response downloads `4R + 32h` bytes. Salts are
32 host-generated bytes and are not counted as D2H. Pass the preparation's `Timing`
to each response: download bytes/time and host assembly time accumulate, including
duplicate requests. Root transfer time stays in the Merkle phase, as before.
Retained device buffers are `4RN + 32(2N-1)` bytes. The existing explicit-buffer
peak includes preparation metadata and transition overlap; it is not a complete
runtime allocation measurement or evidence of RFC-0014 A1's 40% condition.
Context/module setup, caller-owned message storage and overall wall time remain
outside these phase counters and must be charged by any performance campaign.

Tests first: host payload tests rejected the missing helper before implementation.
They compare requested payloads with production `PreparedSource` and reject
malformed geometry, sizes, indices and noncanonical words. Required CUDA test
`matches_reference_resident_source_on_device` compares roots and eight requests
per source across 1000 fixed seeded cases, including duplicate/reversed and edge
indices; checks ordinary authentication and one-word `RootMismatch`; checks
root-only behavior and transfer accounting; and refuses absent CUDA. The existing
1000-case complete-material device test remains required after this refactor.

On Lucid job 6773, all eight requested openings per source matched the CPU
reference across 1,000 seeded cases. The existing 1,000 complete-material cases
also passed. The [actual H100 receipt](../../agents/reviews/e16-40q-h100.json)
records the six selected tests, their resource usage and pinned binary hashes.
Mandatory merge gates still precede integration. A performance comparison must
use the same requested outputs and host, including cold setup, uploads, downloads
and salts.
