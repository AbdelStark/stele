Workflow 03 checklist:
- Public items: research-only matrix/record constructors. No production API.
- Challenges: none. Ordinary identifier/data/Merkle hashing is not a new FS
  challenge. No code profile, proximity or concrete hash budget is certified.
- Claims/consumers: expected roots derive only from complete canonical data,
  verifier-owned code/context and exact function closure. Membership under a
  wrong table's honestly constructed root is explicitly insufficient.
- Bindings: one correction output and one field-congruent integer alias test
  distinct definition/canonical-byte failures. Metadata/root mutations reject.
  These are research assertions, not NC-0412/0413/0414/0701 execution or credit.
- Ledger: no new challenge, loss or profile line. Existing accounting remains.
- Bounds: descriptor-derived shapes, code message length and distinct bounded
  tree ids checked before coding. No witness-derived field-faithfulness bound.
- Padding/masks: every tuple column and prescribed zero row enters the matrix.
  This does not prove a valid-row selector or membership at a real input.
- Determinism: fixed M31 lifts, complete code bytes, raw-id ordering, exact
  little-endian record and Merkle contexts; empty closure is explicit.
- Parity: independent framing plus real code/Merkle arithmetic, including both
  accepted code families and maximal padded rsqrt. Native parity remains E5-02.
- Cost: all generation, coding and hashing retained. No measurements, c_lu
  result, extra weight pass or new cut.
- Verifier: no native change or untrusted admission shortcut. Explicit-row
  arithmetic exists only to construct attacks; expected records regenerate rows.
- Glossary: function manifest, table-data digest and table root stay distinct
  from the full cqis_id/passport and actual PCS acceptance.
