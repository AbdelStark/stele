# Certified functional study review (Q27 / Draft RFC-0010 A3)

Reviewer: codex-root, also author. Same-author pcs-engineer, soundness-auditor
and rfc-author passes; not independent review or production protocol approval.

Theorem provenance: Diamond–Posen Theorem 2, published CIC 1(1), p.10, was checked
against the exact one-third-distance radius, independent tensor randomness and
interleaved column metric. Only that certificate lemma is imported. The near-row,
general batch, grouped batch and lifetime arguments are separately derived here;
no extraction or Fiat–Shamir theorem is inferred from the paper's name.

Workflow 03 checklist:
- Public items: no new production API; the helpers enumerate ideal finite fields.
  They are not parsers, cryptographic source resolvers or certificate receipts.
- Challenges: oracle fixed before certificate row draws; t before its columns;
  complete batch before gamma; all group rows before fresh opening columns.
  Production labels, bytes and unbiased sampling still require A3 completion.
- Claims/consumers: one near M* for a fixed oracle, arbitrary row functionals,
  separate equations per b group and a scalar check. No external checkpoint,
  packed-value, CQIS or private-source consumer is supplied by this study.
- Bindings/controls: four explicit premise attacks; no production NC credit.
  A certificate for another oracle does not establish proximity of this oracle.
- Ledger: candidate certificate gap/query, opening query and batch RLC terms
  are explicit. Adaptive attempts use a union bound, not independent-success
  assumptions. Production accounting, setup/FS/H and profile totals are unchanged.
- Certificates: this is code proximity, not a static integer bound certificate.
- Padding/masks: the matrix dimensions are exact; no implicit padding or blinding.
  Plain rows/columns reveal information, so no zero-knowledge claim follows.
- Determinism: fixed seeded fixtures, exhaustive finite loops and first-occurrence
  exact-vector grouping. No floating point or randomized test result.
- Parity: independent column predicates/query enumeration and exact minimal-query
  arithmetic pass. No native protocol, extension-field or GPU parity is claimed.
- Cost: O(k*R*C) ungrouped or O(g*R*C) grouped row work, full statement preparation,
  encoder workspace and query/consumer work. The single traversal example is an
  algebraic schedule; actual fused-B identity and production pass counts remain.
- Verifier: no core or no_std change; research assertions assume valid fixtures.
  Actual resource admission, canonical field decoding and parser errors are open.
- Glossary: existing claim, functional opening, certificate and ledger terminology.

the research control check_attacks_and_reuse rejected it when every row/group
equation was checked. The intentionally aggregated equations accepted that
attack, demonstrating why they cannot replace those checks. Late values and

Recommendation: retain A3 Draft and E4-03 blocked while continuing with complete
native certificate/root/cache binding, extraction, packing, ZK and Q12. The
