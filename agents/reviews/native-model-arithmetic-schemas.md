# Nineteen native model-arithmetic schemas — E5-03

Same-author `cqis-numerics` and `soundness-auditor` review of RFC-0025's
static arithmetic appendices. This extends the foundation checkpoint with
schemas 7–13 and 15–19. All nineteen standalone schemas now have native
derivation and reference parity. The ordered Bounds collection, original-source
conversion, assigned native controls and complete E5-03 qualification remain
required; standalone records do not supply those boundaries.

The new error type belongs to `bounds::arithmetic`. RFC-0022's original record
constructors, error domain and bytes remain unchanged. Closed parameter types
check every domain before deriving values. No caller supplies generic terms,
a prime, a radix or witness-dependent maxima. Full-frame comparison retains
every scalar, parameter, role, term, cap and boundary carry.

Score derivation uses the original whole-row policies. Their restored bounds
keep the unshifted product below 2^62, and checked u2304 arithmetic retains all
shifted words. Capped division at 2^31 followed by rejection at that endpoint
implements the exact static admission predicate, including larger quotients.
The returned bound belongs to the successfully completed score record. Rotary
addresses retain the complete declared context and the coupled Q14 envelope.

Weighted and normalization records use radix 16. Exact mode counts every context
slot; block mode always derives H from 1024 slots, even at context one. A rounded
full block above 32767 rejects before any record can be returned. Zero rounded
bounds remain legal and retain all roles. Normalization derives its quotient
from Dmin while preserving the same variable Dmax, including the 2^64 endpoint.

Exp records retain the selected direct/product/corrected component order and
inclusive domain endpoint. Activation records retain all five accepted function
kinds and canonical sign-extended source words. These static checks do not
substitute for complete table generation, lookup membership or family selection.

Temperature retains its reduced positive ratio and one rounding, with a quotient
bound capped at the exp domain as prescribed; an actual out-of-domain argument
still rejects at execution. Sampling retains the full permutation/prefix roles,
inclusive 2^32 CDF endpoint and four original draw bytes. Request records retain
full capacity rather than observed lengths. Physical records derive dimensions
and ordinals from checked Shape, retain int4 odd-tail rules, separate matrix and
vector formats, and include complete matrix scale addresses. GPT-2 has no added
physical head record.

The new bounded fixture generator calls qualified pure reference derivations.
Together with the foundation, tests cover 3,757 valid configurations, 73 complete
byte records and 108 expected score/block rejections. Physical fixtures include
every record of both original named geometries, maximal dimensions and odd int4
payloads. Additional tests reject malformed domains, inactive parameters,
nonreduced ratios, substituted formats and wrong ordinals. Full-byte mutations,
truncations and suffixes cannot pass a generated expected record. The independent
wide arithmetic and old RFC-0022 tests remain active.

## Workflow 03

1. New APIs implement attention §§1–3, function §§1–3, weighted §§1–3,
   decoding-bound §§1–3, request §4 and physical §§1–3 of RFC-0025.
2. No challenge, transcript or absorb order changes.
3. No field claim is emitted. Required source, arithmetic, range, branch, index
   and lookup consumers remain separate tasks under the Accepted contract.
4. The tests reject violations at this static boundary. No assigned NC id or
   complete claim-graph binding is marked done by standalone record parity.
5. No soundness-ledger line changes; there is no new random challenge or query.
6. All nineteen schemas are static. The full Model/Scales/Registry association,
   ordered collection and its complete validation still need implementation.
7. Full context/block/component padding and index bounds are retained. Actual
   selectors, inactive lookup exclusion and source joins remain mandatory.
8. Fixed role/component order and exact integers determine all record bytes.
9. Native/reference metadata parity passes on the stated fixtures. Neither
   GPU/proof-byte parity nor named-checkpoint inference is claimed.
10. Static derivation remains T_misc. No weight pass or measured cost-model
    constant changes; no performance result is claimed.
11. The crate remains `no_std`; checked words and bounded fallible record storage
    return no partial public record on failure.
12. Existing Model, Scales, Registry, Bounds and operation vocabulary is retained.
