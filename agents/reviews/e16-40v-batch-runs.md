The host visits every original claim contribution, including zero coefficients, and checks its data position. Each run contains contiguous positions in one tile and claim. The second pass inserts runs in their original order within a tile. Each cursor finishes at its tile's end, so rotation and a zero first entry recover the starts and final sentinel even for empty tiles. A single CUDA thread owns each data position and accumulates matching contributions in that order. Zero-initializing the whole weight buffer supplies the masked face.

The device reference test lifts only message, weight and gamma field limbs into the lazy range. Host and device comparisons retain repeated positions, overlaps, reversals, tile boundaries and both field representations. The transfer count covers the five uploads, including empty-buffer sentinels. The explicit construction peak includes the weight and face allocations. The schedule count is the number of position/run visits across tiles. This was a source review. Physical parity, actual T32 timing and complete pipeline memory require their own measurements.
