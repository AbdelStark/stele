# Global attention offset review — Draft research

Same-author review, not independent audit. Full source ownership, native
integration and original task acceptance remain open.

1. Public items: Draft RFC-0004 A3/A6, RFC-0009 A2 and the pre-implementation
   global-offset scope specify both accumulation modes, canonical stream and
   complete range/byte-column/projection/A1 consumers. Accepted text is unchanged.
2. Challenges: every complete range/lookup uses its existing transcript.
   Full schema, ordered expected roots, internal roots and verified child
   states precede a+3 Sumcheck projection draws. A1 absorbs its instance and
   each round before its bb draws; final claims are absorbed. No new label.
3. Claims: each child uses its complete verifier. The parent consumes one
   actual projected block vector at the receipt's point through verify_public.
   Replay rehashes every original block, including high planes and padding.
   Native linear-view/PCS claims remain a separate obligation.
4. Bindings: controls cover every block/output root, record order/count/type,
   padded source words, valid changed blocks preserving their total, spool
   mutation/truncation/extension, substituted projections, fresh wrong carries
   and a freshly ranged output alias. Full control execution remains pending.
5. Ledger: the appended account keeps B+3 independent lookup identities,
   unsquared lookup reductions and all range losses. Projection a+3 and A1 bb
   are separate. Runtime receipt checks and the repository gate are required.
6. Bounds: only configured source caps determine carry caps; each carry is
   at most B-1, final carry is zero and both byte-column sides are at most
   256B-1<p/2. Full geometry and maximum parent namespaces passed.
7. Padding/masks: complete child caps force zero padded channels, including
   carry planes. External roots preserve eight planes. The small A1 pads
   absent blocks with public zeros. All real blocks remain mandatory.
8. Determinism: source order, child identities, byte planes and transcript
   framing are fixed. Temporary filenames/content timing never enters a hash.
   The verifier copies expected roots before consuming caller-controlled records.
9. Parity: no CPU/SIMD/CUDA core changes. This full-reveal Python research
   does not establish native or GPU parity; those gates remain required later.
10. Cost: O(B*N) byte work and O(N*d+B) parent storage plus one complete child
    proof and B*8N spool bytes. Child peaks and caller/codec storage remain
    additional. No measured constant, extra weight pass or benchmark is claimed.
11. Verifier: native no_std code is unchanged. Expected shapes bound record
    counts, source lengths and all allocations. EOF is mandatory; private
    temporary files close on success or failure. Returned receipts cannot
    replace complete source verification. Native malformed-codec tests remain open.
12. Vocabulary: existing block, offset, carry, source and claim terminology
    is retained. The glossary gate remains required.

The original 10000-case integer corpus passed over 52244 source cells, plus

independent integer dot product. Complete proof controls/matrices, maximum
proofs and repository gates remain running or queued; approval is pending.
